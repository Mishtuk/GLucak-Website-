### `.github/workflows/daily.yml`
- :7-8 `permissions: contents: write` is workflow-wide, so the `deploy` job (:24-32, runs curl with a secret) gets a write token too
  (zizmor `excessive-permissions`). Fix: top-level `permissions: {}`, `contents: write` on the `daily` job only.
- :13 `actions/checkout@v4` leaves the token in `.git/config` (`artipacked`). Add `persist-credentials: false` if
  `tools/preview.mjs --publish` gets its auth from the `GITHUB_TOKEN` env (:22); verify with one `workflow_dispatch` run.
- :13-14 actions pinned to tags, not SHAs (`unpinned-uses`). Pin to full SHA with a `# v4.x.y` comment; dependabot's
  github-actions entry keeps them fresh.
- :14-17 `cache: npm` in a job that publishes to gh-pages (`cache-poisoning`). Low risk (no fork PRs run here); note, or drop the cache.
- No `timeout-minutes` and no `concurrency:` (`concurrency-limits`): a hung step runs up to 6 h; two runs can race on gh-pages.
- :18 `npm ci` runs every dependency's install script. `--ignore-scripts` is probably fine (sharp ships prebuilt binaries); `npm test` will fail loudly if not.
- `.github/dependabot.yml`: no `cooldown:` (`dependabot-cooldown`). Add `cooldown: { default-days: 7 }` to both ecosystems.

### `server.js`
- :335-339 Node default timeouts only; `readBody` (:136-145) has no idle timer, so a slow-loris client holds a socket up to the
  300 s default `requestTimeout`. Set `server.requestTimeout = 60_000; server.headersTimeout = 15_000` before `listen`.
  60 s covers a 5 MB phone upload. Extend `test/stress.test.js` with a stalled body.
- :32-33 `baseHeaders` has no `Cross-Origin-Opener-Policy: same-origin` (helmet default; no popups on the site, embeds are iframes,
  so safe). Leave CORP off (`/media/*` may be hotlinked by Gabe's socials).
- :28 CSP lacks `upgrade-insecure-requests` (one token, free). `img-src ... https:` allows any https image; narrow only if the
  site uses a known host list. `style-src 'unsafe-inline'` is the documented Astro trade-off (csp-evaluator rates it low for styles).
- :286-287 the junk-Host 400 and :296 405 are the paths where headers are built by hand (:286 sends none of `baseHeaders`);
  :147 `redirect` and :98 signup 303 call `baseHeaders` themselves. A header test over these paths would catch a regression.
- `test/server.test.js:38-40` asserts only `frame-src` and `script-src`. Add one table-driven test: for `/`, `/edit/`, a 404, a
  405, a 303, a JSON API reply and a static asset assert nosniff, Referrer-Policy, Permissions-Policy, X-Frame-Options, `object-src 'none'`,
  `base-uri 'self'`, `form-action 'self'`.
- :267 upload writes with no cap on the uploads folder. 30 uploads / 10 min per editor (:255) is about 4300 / day, 40 MP each
  at WebP; a stolen session could fill the disk. Add a file-count or bytes check before `writeFileSync`.

### `src/lib/*`
- `auth.js:36-38` cookie `HttpOnly; SameSite=Strict; Path=/edit; Secure` is right (`__Host-` is impossible with `Path=/edit`; accept).
  Session is stateless HMAC: `logout` (`server.js:234`) clears only the browser copy, a stolen cookie lives up to 7 days
  (`auth.js:7`); mitigation present (a password change ends sessions, :11-12). Panic button idea: fold an env `SESSION_EPOCH` into the MAC (S).
- `auth.js:80-105` in-memory limits reset on restart: documented `ponytail:`, fine for one process.
- `signup.js:134` a request with neither Origin nor Referer passes. The per-IP limit (:121) is the real defence, but there is
  no global cap (the edit login has `login:all`, `server.js:222`), so a botnet can push many sign-ups to Kit. Add a global 60 / hour (S).
- `upload.js` is already best practice (sharp decode as the gate, pixel cap, re-encode, random name, `wx`, 5 MB cap, type allowlist).
  Optional: limit sharp concurrency to 1 on a small host (a 40 MP decode is large).
