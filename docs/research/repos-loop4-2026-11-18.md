## Top 3 improvements (each fits the hard rules: no dependency, no script, no motion, no photo change)

1. **Block sharp's untrusted loaders in the upload path.** `src/lib/upload.js:13-16`. `sharp(buf).metadata()` (line 15) runs the real decoder for ANY format
   (SVG, HEIF, TIFF, GIF) before line 16 rejects it. sharp published high-severity advisories for exactly those loaders this year: librsvg GHSA-wq5f-xc86-pv6w
   (2026-09-30, possible RCE on glibc Linux), libheif GHSA-rgj7-g3m4-5g8c (2026-08-27), libvips GHSA-f88m-g3jw-g9cj (2026-07-17, GIF / TIFF / VIPS). We are on
   sharp 0.35.5, which has all three fixes, so this is defence in depth against the next one. After the import add (once):
   `sharp.block({ operation: ['VipsForeignLoad'] }); sharp.unblock({ operation: ['VipsForeignLoadJpeg', 'VipsForeignLoadPng', 'VipsForeignLoadWebp'] });`
   Caveat: sharp's SECURITY.md shows the pattern for `VipsForeignLoadJpeg`; the PNG / WebP class names are by analogy and **not tested by me**, so add a test:
   JPG / PNG / WebP still pass, SVG / GIF / TIFF / HEIC give `not_image`. Source: lovell/sharp `.github/SECURITY.md` and the three advisories, Apache-2.0.
   `tools/photo` runs in its own process and is unaffected.
2. **Raise the scrypt cost to the OWASP minimum.** `src/lib/auth.js:42` (`N: 16384, r: 8, p: 1`, used at lines 44 and 50). OWASP Password Storage Cheat Sheet
   (lines 12, 126-130; CC-BY-SA-4.0, cited only) says scrypt needs N=2^17, r=8, p=1, or an equal pair such as N=2^15, r=8, p=3 (32 MiB). Our N=2^14 with p=1 is
   below every listed pair (2^14 needs p=5). Node's default `maxmem` is 32 MiB, so pass `maxmem` (about 64 MiB for 2^15, 256 MiB for 2^17) at lines 44 and
   50. **Breaking:** the stored `<salt>.<hash>` carries no parameters, so every hash in `EDITOR_USERS` must be regenerated with `tools/hash-password.mjs`
   (the owner's deploy secret changes). I suggest 2^15 / p=3 for a small App Service plan; I did not measure the time or memory on the host.
3. **Make sign-out end the session on the server.** `server.js:262` (`/edit/logout` only clears the cookie) and `src/lib/auth.js:22-34` (`verifySession`). A copied
   cookie stays valid for the full 7 days after Gabe signs out; only a password change ends it. OWASP Session Management Cheat Sheet lines 313-317 and 355
   (CC-BY-SA-4.0, cited only) say logout must invalidate the session server-side. Lazy fix (about 5 lines): a `Map` name -> logout time; `verifySession` returns
   null when `exp - SESSION_DAYS*864e5 <= loggedOutAt` (the issue time is already implied by `exp`). Ceiling: memory only, a server restart forgets it; a
   `ponytail:` comment can name that. The same cheat sheet wants an idle timeout; we keep 7 days absolute for a phone user, an owner call.

Dropped on purpose: `__Host-` cookie prefix (needs `Path=/`, ours is `Path=/edit` by design), adding rate-limiter-flexible or helmet (no new dependency), AVIF.
